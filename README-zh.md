# dsh-skill-browser

> 悬浮球打开面板，把本机技能库变成可浏览、可检索、可治理的资产：两级分类 + 自定义分组（树状/平铺双模式、手动建组、⚡ 关键词分组、🤖 AI 自动分组与 AI 封面，**分组只改视图，不动技能文件**）、版本号徽章（无版本显示「暂未编版本号」）、单卡/分类/全库启停（自动备份）、SKILL.md 全文查看；内置调用台账看板（起止日期 + 日/周/月/年 + 排行榜 + 趋势图 + 失效明细），监听 `tools/result` 自动登记每次技能调用结果。⚡ 一键热重载，128 款皮肤全量自适应配色，技能库位置可配置，悬浮球可拖拽可复位。

> 完整文档以 [English README](./README.md) 为准，本页提供中文导读与关键信息速查。

## 功能

浏览本地技能库、关键词检索、查看技能详情与触发词、快速路由到目标技能。

### 全皮肤自适应配色（v1.9.2）

面板支持 128 款皮肤，其中 20 款是浅色皮肤。v1.9.0 / v1.9.1 新增的台账看板与分组栏原先用深色硬编码，浅色皮肤下会白字白底看不清；现在全部改用皮肤语义变量：

- `--dsb-ok` / `--dsb-fail` / `--dsb-warn`：成功 / 失败 / 警告三色，深色皮肤用亮色系、浅色皮肤自动切深色系
- `--dsb-dim`：次要小字专用色，按 `hintC → itm → ptx → 兜底` 候选链取第一个达标色（4.8:1 余量，按卡片底而非面板底核算）
- `--dsb-brand` / `--dsb-brand-strong`：品牌强调色当**正文**用的版本。技能名、排行榜技能名、排序高亮、分组标签不再直接吃 `--stA`，而是沿「同色相逐级加深」阶梯算出达标色 —— 08 极地冰川原为 2.80:1、04 全息幻彩 2.9:1，现全部 ≥ 4.5:1（大数字 3:1）
- `--dsb-onbrand`：品牌渐变上的标签色，按渐变中点亮度自动在白 / 近黑之间切换，淡渐变上不再出现白字
- `--dsb-bar1` / `--dsb-bar2`：趋势柱与排行迷你条，按非文字图形标准 3:1 取达标色
- `--dsb-soft` / `--dsb-line` / `--dsb-hover`：分隔线、悬停底色
- `--dsb-scheme`：`light` / `dark`，驱动原生 `<input type="date">` 日历弹窗配色

切换皮肤后无需刷新，配色随皮肤即时重算。128 款皮肤 × 18 组前景/背景组合共 2304 项已全量校验，0 项不达标（`scripts/audit-contrast.mjs` 可随时复跑）。

> **v1.9.5**：排行榜表头是吸顶的，底色改用语义变量 `--dsb-surface`（行/卡片真实不透明底色），滚动时不会再和行文字重叠。
>
> **v1.9.9**：再加固一轮「小字可见性」——
> - `.dsb-gn` 数字徽标改为**继承父级文字色**（它同时出现在工具条、激活渐变按钮、大类深底三种背景上，写死白色必然有一处看不见）
> - 基础 CSS 里 24 处 `var(--itm)` 文本色统一换 `var(--dsb-dim)`（皮肤自带 `--itm` 在 28 款手调皮肤上只有 3.0–4.0:1）
> - 品牌渐变新增安全对 `--dsb-onbrand-bg1/2`，按「白字 ≥4.6:1」反解，浅色皮肤淡渐变自动压深
> - `--dsb-ok` / `--dsb-fail` / `--dsb-warn` 作为 10–11px 文本时按卡片底再走一遍 4.8:1 阶梯
> - 语义色小字专项审计 1024 项，0 项 < 4.5:1

### 调用台账看板（v1.9.1）

「📊 调用台账」tab 从原来的失效流水列表改为统计看板：

- **时间区间**：7 个快捷区间（今天 / 近 7 天 / 近 30 天 / 本月 / 上月 / 今年 / 全部）+ 自定义起止日期
- **聚合粒度**：日 / 周 / 月 / 年（周以周一为起点，空洞自动补零）
- **6 个指标卡**：调用次数、活跃技能数、活跃天数、成功率、失败次数、日均调用
- **趋势柱状图**：纯 CSS 柱状图，失败全部命中的柱标红，悬停看具体数字
- **技能调用排行**：调用 / 成功 / 失败 / 成功率 / 最后调用时间 + 版本徽章 + 相对量迷你条；5 个表头可点击切换排序；失败次数 > 0 的行可点开该技能的人工台账明细
- **原始流水折叠**：人工台账表与最近 30 条自动登记流水默认收起，需要时展开

数据来源是插件自己监听的 `skill` 工具调用结果（`技能失效-自动登记.jsonl`），不额外上报任何东西。

### 技能版本号徽章（v1.9.0）

卡片技能名旁显示 `v<version>` 绿色徽章。版本读取顺序：

1. `SKILL.md` frontmatter 的 `version` 字段
2. 同目录 `package.json` 的 `version` 字段

两者都没有时，显示灰色「暂未编版本号」。

### 自定义视图分组（v1.9.0，v1.9.3 升级为两级，v1.9.8 加树状视图）

面板新增「我的分组」栏，可手动新建分组（名称 + emoji + 颜色），并支持重命名与删除。

- 分组数据存于 `~/.dsh/data/dsh-skill-browser/groups.json`
- **分组只是视图归档，绝不移动或修改任何技能文件在磁盘上的位置**

**v1.9.8 起分组栏有两种显示模式**，工具条上的「🌳 树状」「▦ 平铺」一键切换，选择记在 `localStorage`：

| 模式 | 样子 | 适合 |
|---|---|---|
| 🌳 树状（默认） | 每个大类独占一整行，子类**常驻**缩进挂在下层，用 `├─` `└─` 树枝连接符 + 竖引导线画出层级 | 想一眼看全「哪个大类下面有哪些子类」 |
| ▦ 平铺 | v1.9.3 原样：大类排成卡片，点开才显示子类栏 | 习惯旧视图、分组很多想省纵向空间 |

工具条统一为：分组标题 · 全部 · 未分组 · 🌳树状 · ▦平铺 · ⚡关键词分组 · 🤖AI自动分组 · ＋新建。大类行右侧显示「N 项 · N 子类」，悬停浮出 🎨 / ＋ / ✏️ / 🗑 四个操作。

**v1.9.3 起分组是「大类 → 子类」两级结构**，用来表达逻辑上的总-分关系：

- 大类 = 领域（如「Fluent/CFD 仿真」「DSH 工具链」「软件安装」「网关与反代」）
- 子类 = 该领域内的具体用途（Fluent 下：前处理 / 画网格 / 求解与监测 / 后处理 / 故障排查；DSH 下：启动失败 / 插件冲突 / 插件开发 / 安装经验 / 网关配置）
- 层级上限两层，第三层会被拒绝；大类行显示「N 项 · N 子类」，数量是该大类自身成员 + 全部子类的合计
- 点大类看全部，点子类就只看那一个；树状模式下子类一直可见，平铺模式下选中大类后才显示子类栏
- 大类行上的「＋」按钮可直接在该大类下新建子类

### 一键把技能移入分组（v1.9.0，v1.9.3 支持两级）

每张技能卡片底部有「📁 移动」按钮，点开浮层选择目标分组即可归档；浮层按层级缩进列出「大类」与「└ 子类」，技能可以直接挂在大类上，也可以挂到更细的子类；卡片上同时显示当前所属分组标签，也可选择「移出分组」。

### 关键词快速分组（v1.9.7）

分组栏新增「⚡ 关键词分组」按钮，**完全不调模型**：`lib/keyword-groups.js` 用技能目录名的关键词正则直接切出「大类 → 子类」两级方案。

- **零 token、毫秒级**：实测 111 个技能 1~2ms 出方案（AI 分组要几十秒且可能被 max-tokens 截断）
- **结果完全确定**：同一批技能每次分组结果一样，不会今天一个样明天一个样
- **单子类硬上限 8 个**（`KEYWORD_MAX_SUB`），超过自动拆成「名称 1」「名称 2」，解决 AI 分组「太满」的问题
- **全覆盖**：未命中关键词的技能归入「其他技能」，不会丢
- 与 AI 分组共用同一个方案确认弹层：先看方案，再选「替换」或「追加」才写盘，不确认不落盘

AI 分组与关键词分组是并列的两条路：想快、想稳定就用 ⚡；想按语义细分就用 🤖。

### AI 自动分类建组（v1.9.0，v1.9.3 改为先出方案再落盘）

分组栏的「🤖 AI 自动分组」按钮调用 DSH 宿主 llm 服务，读取技能库清单（目录名 + 中文简介 + 现分类），让模型输出**两级**分组方案（`大类 → 子类 → 技能`）。

**v1.9.3 起 AI 只产出方案、不直接写盘**：方案会在弹层里列清楚（共 N 个大类 / M 个子类 / 覆盖 K 个技能），由用户选：

- **替换**：清掉旧的 AI 分组，按此方案重建（手工建的分组永远保留）
- **追加**：保留现有分组，只补还没归类的技能

不确认就不写盘，分得不满意可以直接取消重来，不用先删一堆组。

分类提示词按「领域 → 用途」两级重写：每个技能恰好归一个子类、一个不漏；单子类 ≤10 个技能；禁止「通用 / 其他 / 杂项 / 综合 / 工具集」大杂烩筐；不再因为某领域技能多就只细分它。

v1.9.2 起改为**三遍覆盖式分类**，解决「只分了 Fluent、其他技能全丢进一个杂项筐」的问题：

1. **第一遍**：全量技能交给模型，大类数按规模自动定（技能数 ÷ 12 向上取整，3~16 个，允许 ±2），每个大类下分 1~6 个子类，单个子类上限 10 个技能，提示词明确禁止「通用工具 / 其他 / 杂项 / 综合」这类筐，并要求各领域拆分粒度一致。
2. **第二遍**：把模型漏掉的技能单独再问一次，并要求避开第一遍已建的分组名，让它们得到真正的语义分组，而不是一个「其他」大筐。
3. **第三遍（不调模型）**：仍未覆盖的技能按自身分类标签兜底成组，单个子类超过 10 个技能时自动拆成 `名称 1` / `名称 2`。

因此 AI 分组后**不会再出现「未分组」堆积**，全部技能都会落到某个组里。

只重建 AI 建的组，保留用户手工建的组。

### AI 一键生成分组封面（v1.9.0）

每个分组卡片右上角有「🎨」按钮，调用 llm 生成一段纯 SVG（200x200，深色渐变 + 几何装饰 + 居中符号，无文字），经安全清洗（剥 `<script>`、`on*=` 事件属性、外部 href，上限 40KB）后存入 `groups.json`，作为分组卡片背景图。

### AI 能力为可选（v1.9.0）

`@deepseek-ai/dsh-llm` 声明为 `optional peerDependency`：不安装也能正常使用全部非 AI 功能，只是两个 AI 按钮会提示「AI 不可用」。

### 零配置模型自动发现（v1.9.9）

**别人装完插件不用填任何配置，AI 分组 / AI 封面就能用** —— 插件按四段式自动找「你正在用的那个模型」：

1. 插件配置里显式写了 `provider` + `model` → 直接用（`source: config`）
2. 当前对话会话绑定的模型（`ctx.agent.session`）→ `source: agent-session`
3. DSH 设置页选的默认模型（`agentDefaultModel.currentSelection()`）→ `source: dsh-default`
4. 兜底扫宿主可用模型目录，取第一个 → `source: llm-catalog`

分组工具条右侧有一个**模型探针徽标**，常驻显示「🤖 AI 分组将使用：deepseek-v3（DSH 默认模型）」，点一下可重新探测：

- 探测**只读配置，不触发任何模型调用**，也不写 `groups.json`
- 宿主没提供 llm 服务、或一个默认模型都没选时，徽标直接变红并提示「没找到任何可用模型，请到 DSH 设置 → 模型 选一个默认模型」——不用等真点分组失败才发现
- 关键词分组（⚡）完全不走模型，任何情况下都可用

### 热重载（v1.9.4）

面板右上角的 **⚡** 按钮：改完插件代码点一下，host 半当场换新、界面刷新取最新 bundle，**不重启桌面端、不中断会话**。

- host 半：`POST /dsh-skill-browser/reload` → 用 `?v=<ts>` 重新 import 自身模块（含 5 个子模块），新 API 实例接管请求，旧的 `dispose()` 释放；生效句柄挂在 `globalThis.__DSB_LIVE__`，`gen` 自增，监听器不重复注册。
- client 半：调 `clientModules.rebuilt(id)` 让宿主重读 `client.js`，随后页面刷新。
- 探针：`GET /dsh-skill-browser/rev` 返回 `{version, gen}`，面板轮询确认 `gen` 变大后才刷新，避免刷到旧代码。
- 适用范围：只换本插件代码。改了别的插件、或改了宿主本体，仍需重启桌面端。

### 性能与分片渲染（v1.9.6）

技能库到一百多个之后，原来「一次性把全部卡片和全部调用流水拼进 innerHTML」会明显卡顿、内存也高。v1.9.6 改成按需分片：

- **技能卡片**：一次只渲染 60 张，滚动到底自动追加 60 张；也可以点「加载更多（还有 N 条）」。切换分类 / 搜索 / 排序 / 分组时自动重置回 60。
- **原始流水**：一次只渲染 120 行，点「加载更多」追加 120 行。
- **追加时保留滚动位置**，不会跳回顶部。
- **列表是静态摘要**：卡片只显示目录名、中文简介、分类、版本徽章、修改时间；**SKILL.md 全文只在点开详情时才 fetch**（v1.9.0 起就是惰性加载，v1.9.6 保持）。
- **jsonl 增量读取**：宿主新增 `autoLogStat()`（只 stat 拿 size+mtime）和 `readAutoLogTail(root, n, skill?)`（从文件尾部按行切齐读）。「最近 30 条」不再为 30 条记录读整个 jsonl。
- **统计缓存加 stat 探针**：`/ledger/stats` 的缓存键并入 jsonl 的 size+mtime，文件没变时切粒度/改排序直接命中，且同一份 jsonl 只解析一次。
- **单技能明细分页**：`/ledger-detail` 默认只回最近 200 条（`&limit=` 可调），并返回 `autoTotal`，前端显示「共 N 条（仅显示最近 M 条）」。

> **v1.9.6**：详情页（点技能看全文 / 点台账看失败明细）里，排行榜的吸顶表头曾浮在详情层之上，正文里横插一条表格头。详情层 `z-index` 提到 20，彻底压住。

### v1.9.1 新增台账统计接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/dsh-skill-browser/ledger/stats` | 调用台账聚合统计（区间 / 粒度 / 排行 / 趋势） |

查询参数：

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `from` | `YYYY-MM-DD` | 空（不限） | 起始日期（含） |
| `to` | `YYYY-MM-DD` | 空（不限） | 结束日期（含） |
| `gran` | `day` / `week` / `month` / `year` | `day` | 聚合粒度；周以周一为起点 |
| `sort` | `calls` / `fails` / `rate` / `last` / `name` | `calls` | 排行榜排序字段 |
| `top` | 正整数 | `200` | 排行榜返回条数上限 |

返回结构：`{ ok, gran, from, to, sort, dataFirst, dataLast, totals:{calls,ok,fail,rate,skills,days,avgPerDay}, buckets:[{key,label,calls,ok,fail}], ranks:[{skill,calls,ok,fail,first,last,rank,rate}], rankTotal }`。带 30 秒缓存；`from > to` 会自动交换。

### v1.9.0 新增分组接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/dsh-skill-browser/groups` | 列出分组 + 技能归属映射 |
| `POST` | `/dsh-skill-browser/groups` | action = `create` / `rename` / `delete` / `move` / `assign` / `assign-batch` / `ai-classify` / `kw-classify` / `ai-apply` / `ai-cover` / `model-info` |

`ai-classify` / `ai-apply` / `ai-cover` 需要宿主 llm 服务（`@deepseek-ai/dsh-llm`）；未安装时该 action 返回「AI 不可用」。

`kw-classify`（v1.9.7）**不需要 llm**：本地正则直接出方案，返回 `{ok, plan:{domains}, stats, mode:"keyword", unmatched}`；方案确认后仍走 `ai-apply` 落盘。

`model-info`（v1.9.9）**不调模型、不写盘**：返回 `{ok, provider, model, source, error}`，`source` ∈ `config` / `agent-session` / `dsh-default` / `llm-catalog`。面板用它渲染「AI 分组将使用：xxx」徽标，实现零配置可用性自检。

### v1.9.4 新增热重载接口

- `POST /dsh-skill-browser/reload` → `{ok, version, gen, reloading}`；用 `?v=<ts>` 重新 import 自身模块，换掉正在服务的 handler。
- `GET /dsh-skill-browser/rev` → `{ok, version, gen, ts}`；`gen` 变大表示宿主半已换代。
